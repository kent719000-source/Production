## 1.システム概要

### 背景

架空の犬・猫保護団体（常勤スタッフ3名、ボランティア10名、上限保護頭数30頭を想定）へのヒアリングを想定し、以下の課題を設定した。各課題の設定には(https://www.animaldonation.org/awgs/report/hakusho2025/)を参考にした。

- 現在何頭を保護していて、あと何頭受け入れられるかがすぐに答えられず、保健所や市民からの新しい保護依頼への返事が遅れる。
- 事務作業（個体の記録、予定の管理、里親希望者への連絡など）に1人あたり1日1時間前後を取られ、動物の世話や譲渡活動に時間を割けない。
- 個体・イベント・里親の情報が紙のカルテ、Excel、スタッフ間のチャット、担当者の記憶などに分かれて置かれていて、担当者が休むと予定や経緯が分からず、伝達ミスや対応漏れが起こる。

### 本システム
本システムは、上記の情報をブラウザから登録・閲覧・更新できるWebシステムである。扱う情報は次の4種類に絞る。

| 情報 | 内容 |
|:---:|:---:|
|個体|保護している犬・猫の基本情報、写真、保護日と保護場所、避妊・ワクチン・マイクロチップの状況、<br>健康や性格の特記事項、保護状況（保護中(譲渡可)・保護中(譲渡不可)・入院中・トライアル中・譲渡済・返還・移管・死亡）|
|イベント| 通院、ワクチン接種、トライアル、譲渡などの予定と実施記録<br>対象の個体、日程、場所、費用、対応済か未対応か|
|里親| 里親希望者および譲渡先の連絡先と特記事項|
|スタッフ| 団体のメンバーと権限（管理ユーザー・常勤スタッフ・ボランティア）、ログインID|

トップページでは、今月のイベントをカレンダーで、現在の保護頭数と団体の受入上限、空き頭数を数字で確認できる。空き具合は「受け入れOK」「残りわずか」「満員」の3段階でも表示する。

本システムは複数の保護団体が共同で利用する。各団体は自団体のデータのみを閲覧・操作でき、他団体のデータを見ることはできない。<br>団体と最初の管理ユーザーは運営が登録し、以降のスタッフのアカウントは団体の管理ユーザーが発行する。

### 導入で何が変わるか
- 保護頭数と受入上限がトップページに常に表示されるため、新しい保護依頼を受けられるかをその場で判断できる。
- 個体の情報は個体詳細ページを開けば揃う。ワクチンや通院の経過はその個体に紐づくイベントとして残るため、人に聞いて回ったり、紙とExcelを突き合わせたりする時間がなくなる。
- 予定は日程つきのイベントとして登録され、団体全員のカレンダーに表示される。未対応と対応済は色で分けて表示されるので、担当者が休んでも予定は見え、未対応のまま日程を過ぎたイベントが残っていれば、対応漏れにその場で気づける。
- 里親の連絡先と経緯をスタッフ全員が参照できるため、担当者が不在でも問い合わせに答えられる。

## 2.対象ユーザー
### 対象ユーザー
犬・猫を保護する動物保護団体のスタッフ（管理ユーザー・常勤スタッフ・ボランティア）

### ユーザーの特徴
- ブラウザの基本操作ができること。
- 特別なITスキルは不要。

## 3.用語定義

|用語|意味|
|:---:|:---:|
|団体|本システムを利用する動物保護団体<br>データは団体ごとに分かれる|
|運営|本システムを提供する開発チーム<br>団体の登録を行う|
|管理ユーザー|団体の代表者など<br>すべての操作（常勤スタッフに加え、スタッフのアカウントの発行・編集、データの削除）ができる|
|常勤スタッフ|団体の職員<br>すべての情報の閲覧と、個体・イベント・里親の登録・編集ができる|
|ボランティア|団体の活動を手伝う人<br>すべての情報の閲覧のみできる|
|個体|現在、保護管理または予定している犬、猫|
|里親|個体を引き取る人、または引き取りを希望している人|
|保護状況|個体が現在どの段階にあるかを示す区分（保護中(譲渡可)・保護中(譲渡不可)・入院中・トライアル中・譲渡済・返還・移管・死亡）|
|保護頭数|団体が現在世話をしている頭数。保護状況が保護中(譲渡可)・保護中(譲渡不可)・入院中・トライアル中の個体の合計|
|受入上限|団体が同時に保護できる頭数の上限（画面では「定員」と表示する）<br>団体ごとに運営が登録する|
|返還|迷子などで保護した個体を元の飼い主へ返すこと|
|移管|個体を他の団体や行政へ引き継ぐこと|
|トライアル|譲渡の前に、里親の家で一定期間個体を試しに飼育すること|
|譲渡|個体を正式に里親へ引き渡すこと|
|イベント|通院・ワクチン接種・トライアル・譲渡などの業務に関する予定と記録|
|対応状況|イベントが済んだかどうかを示す区分（未対応・対応済）<br>対応済にしたスタッフを対応スタッフとして記録する|
|誕生日|出生日。分からない場合はおよそ推測した日を入れ、推定であることも記録する|
|保護日|施設にきた日|
|品種|犬、猫の種類（柴犬、アメリカンショートヘアなど）|

## 4.業務フロー
### ログインページ
1. 正しいIDとパスワードを入力してログインするとトップページへ移動する。
2. IDまたはパスワードが間違っているとエラーメッセージが表示される。

### 共通
1. ログイン後のすべてのページの上部に、ロゴ（トップページへのリンク）、各一覧ページ（個体管理・イベント管理・里親管理・スタッフ管理）へのリンク、ログイン中の団体名と名前、ログアウトボタンが表示される。
2. ログアウトボタンを押すとログインページへ戻り、「ログアウトしました」と表示される。
3. ログインせずにページを開くとログインページへ移動する。
4. 権限の無いページや、存在しないデータ（他団体のデータを含む）のページを開くと、エラーページが表示される。

### トップページ
1. トップページを開くと、「個体管理へ」「イベント管理へ」「里親管理へ」「スタッフ管理へ」のリンクが表示される。
2. 今月のカレンダーが表示され、その日のイベント（個体名・種別・未 / 済）が表示される。未対応と対応済は色で分けて表示される。
3. カレンダーのイベントをクリックすると、イベント一覧ページへ移動し、そのイベントの概要が表示される。
4. 現在の保護頭数と受入上限（定員）、空き頭数、使用状況のバーが表示される。
5. 空きが0頭以下なら「満員」、保護頭数が受入上限の80%以上なら「残りわずか」、それ以外は「受け入れOK」と表示される。

### 個体一覧ページ
1. 個体の一覧がカード形式（写真・名前・犬猫・性別・品種・年齢）で表示される。
2. 犬猫・保護状況・名前で絞り込める。最初は、保護頭数に数える保護状況（保護中(譲渡可)・保護中(譲渡不可)・入院中・トライアル中）の個体が表示される。
3. 新規登録/詳細へのリンクが表示される。(新規登録についてはボランティアの場合は非表示)

### 個体詳細ページ
1. 個体の詳細が表示される。
2. 個体の写真が表示される。
3. 個体に紐づくイベントの履歴が表示される。
4. 編集リンクが表示される。(ボランティアの場合は非表示)
5. 削除ボタンが表示される。(管理ユーザーのみ表示)
6. 削除ボタンを押すと「この個体を削除してもよろしいですか？」とポップアップが表示される。削除すると、その個体のイベントと写真も削除される。

### 個体編集ページ
1. 個体情報の編集フォームが、現在の値が入った状態で表示される。
2. 写真は、新しく選んだときだけ差し替わる。
3. 更新ボタンを押すと個体詳細ページへ移動し、「個体を編集しました」と表示される。
4. 入力エラーがあると、同じページのまま、エラーのある項目の下にエラーメッセージが表示される。

### 個体新規登録ページ
1. 新規入力フォームが表示される。
2. 画像ファイルのアップロードフォームが表示される。写真を選ぶと正方形に切り抜く枠が表示され、切り抜いた写真が登録される。
3. 保護状況がトライアル中・譲渡済のときは、里親を選ぶ。
4. 登録ボタンを押すと個体詳細ページへ移動し、「個体新規登録が完了しました」と表示される。
5. 入力エラーがあると、同じページのまま、エラーのある項目の下にエラーメッセージが表示される。

### イベント一覧ページ
1. イベントがカレンダー形式で表示される。前月・次月・今月に切り替えられる。
2. 未対応と対応済は色で分けて表示される。
3. カレンダーのイベントをクリックすると、そのイベントの概要が概要ペインに表示される。
4. 概要ペインのスタンプ欄を押すと、確認のポップアップのあと、イベントが対応済になる。対応済のスタンプを押すと未対応に戻る。(ボランティアの場合はスタンプ欄の代わりに対応状況が文字で表示される)
5. 対応済にしても、個体の情報（保護状況など）は自動では変わらない。個体の情報は個体編集ページで変える。
6. 新規登録/詳細へのリンクが表示される。(新規登録についてはボランティアの場合は非表示)

### イベント詳細ページ
1. イベントの詳細が表示される。
2. スタンプ欄が表示され、概要ペインと同じように対応済にしたり未対応に戻したりできる。(ボランティアの場合はスタンプ欄の代わりに対応状況が文字で表示される)
3. 編集リンクが表示される。(ボランティアの場合は非表示)
4. 削除ボタンが表示される。(管理ユーザーのみ表示)
5. 削除ボタンを押すと「本当に削除しますか？」とポップアップが表示される。削除すると、そのイベントの月のイベント一覧ページへ移動し、「イベントを削除しました」と表示される。

### イベント編集ページ
1. イベント情報の編集フォームが、現在の値が入った状態で表示される。
2. 更新ボタンを押すとイベント詳細ページへ移動し、「イベントを編集しました」と表示される。
3. 入力エラーがあると、同じページのまま、エラーのある項目の下にエラーメッセージが表示される。

### イベント新規登録ページ
1. 新規入力フォームが表示される。
2. 種別がトライアル開始・譲渡のときは、里親を選ぶ。
3. 登録ボタンを押すと、登録したイベントの月のイベント一覧ページへ移動し、「イベント新規登録が完了しました」と表示される。
4. 入力エラーがあると、同じページのまま、エラーのある項目の下にエラーメッセージが表示される。

### 里親一覧ページ
1. 里親の一覧が表形式（名前・電話番号・住所）で表示される。
2. 名前・電話番号で検索できる。
3. 新規登録/詳細へのリンクが表示される。(新規登録についてはボランティアの場合は非表示)

### 里親詳細ページ
1. 里親の詳細が表示される。
2. 関連する個体（トライアル中・譲渡済）と、関連するイベントが表示される。
3. 編集リンクが表示される。(ボランティアの場合は非表示)
4. 削除ボタンが表示される。(管理ユーザーのみ表示)
5. 削除ボタンを押すと「本当に削除しますか？」とポップアップが表示される。
6. 個体またはイベントに紐づいている里親は削除されず、「個体またはイベントに紐づいているため削除できません」と表示される。

### 里親編集ページ
1. 里親情報の編集フォームが、現在の値が入った状態で表示される。
2. 更新ボタンを押すと里親詳細ページへ移動し、「里親を編集しました」と表示される。
3. 入力エラーがあると、同じページのまま、エラーのある項目の下にエラーメッセージが表示される。

### 里親新規登録ページ
1. 新規入力フォームが表示される。
2. 登録ボタンを押すと里親詳細ページへ移動し、「里親新規登録が完了しました」と表示される。
3. 入力エラーがあると、同じページのまま、エラーのある項目の下にエラーメッセージが表示される。

### スタッフ一覧ページ
1. スタッフの一覧が表形式（名前・性別・電話番号・メールアドレス・ユーザー種別）で表示される。
2. 名前・電話番号で検索できる。
3. 新規登録/詳細へのリンクが表示される。(新規登録については管理ユーザーのみ表示)

### スタッフ詳細ページ
1. スタッフの詳細が表示される。
2. そのスタッフが対応した（対応済にした）イベントが表示される。
3. 編集リンクが表示される。(管理ユーザーのみ表示)
4. 削除ボタンが表示される。(管理ユーザーのみ表示。自分自身の詳細ページには表示されない)
5. 削除ボタンを押すと「本当に削除しますか？」とポップアップが表示される。

### スタッフ編集ページ
1. スタッフ情報の編集フォームが、現在の値が入った状態で表示される。
2. このページは管理ユーザーだけが開ける。ログインIDは変更できない。パスワードは変更する場合だけ入力する。
3. 自分自身のユーザー種別は変更できない。
4. 更新ボタンを押すとスタッフ詳細ページへ移動し、「スタッフを編集しました」と表示される。
5. 入力エラーがあると、同じページのまま、エラーのある項目の下にエラーメッセージが表示される。

### スタッフ新規登録ページ
1. 新規入力フォームが表示される。
2. 登録ボタンを押すとスタッフ詳細ページへ移動し、「スタッフ新規登録が完了しました」と表示される。
3. 入力エラー（既に登録済みのログインIDを含む）があると、同じページのまま、エラーのある項目の下にエラーメッセージが表示される。

|イベント一覧|登録されたイベントをカレンダー形式で表示できること|
|イベント詳細|選択したイベントの詳細情報を表示できること|
|イベント登録|イベントの情報を入力して新規登録できること|

|里親編集|里親の情報を変更して保存できること|
|里親削除|既存の里親を削除できること|
|スタッフ一覧|登録されたスタッフを一覧で表示し、名前・電話番号で検索できること|
|スタッフ詳細|選択したスタッフの詳細情報を表示できること|
|スタッフ登録|スタッフの情報を入力して新規登録できること|
|スタッフ編集|スタッフの情報を変更して保存できること|
|スタッフ削除|既存のスタッフを削除できること|

## 6.非機能要件
|分類|要件|
|:---:|:---:|
|性能|通常操作(作成、登録、編集、削除)、またユーザーのログイン、ログアウトは3秒以内に完了すること|
|使用性|複雑な操作を入れず簡単に誰でも扱えること|
|可用性|本番サーバーは開発環境と同じ構成（8章の言語・フレームワーク・データベース）で動作すること|
|セキュリティ|ログイン認証を行う<br>権限によって操作を制限する<br>他団体のデータは閲覧・操作できない<br>パスワードはハッシュ化して保存する|

## 7.権限
|権限者|できること|
|:---:|:---:|
|管理ユーザー|アカウントの発行<br>全ての個体・里親・イベント・スタッフ情報の閲覧・登録・編集・削除ができる<br>イベントを対応済にする・未対応に戻すことができる<br>ただし、自分自身の削除と、自分自身のユーザー種別の変更はできない|
|常勤スタッフ|全ての個体・里親・イベント・スタッフ情報の閲覧ができる<br>個体・里親・イベントの登録・編集ができる<br>イベントを対応済にする・未対応に戻すことができる<br>削除と、スタッフの登録・編集はできない|
|ボランティア|個体・里親・スタッフ・イベントの閲覧ができる|
|未登録ユーザー|使用不可|
