## 1. 共通仕様

### 1.1 この文書の読み方

- 画面は `S-xx`（基本設計 1 章「画面一覧」の No）。例: S-03 個体一覧
- 機能は `F-xx`（基本設計 4 章「URL 設計」の No）。例: F-05 GET /animal

### 1.2 ログインと権限

- ログインは Spring Security に任せる（Controller は書かない）。ログイン ID とパスワードで staff テーブルを検索し、パスワードは BCrypt で照合
- ログインしたら「自分の ID・団体 ID・権限」がセッションに入る。Controller では `@AuthenticationPrincipal LoginUser login` で受け取る
- 権限は基本設計 4 章のとおり。GET はボランティア以上、POST は常勤スタッフ以上、`/staff/new` だけ管理ユーザー
- 画面のボタン（新規登録・編集・削除・完了）は `<sec:authorize access="hasAnyRole('ADMIN','STAFF')">` で囲んでボランティアには見せない

### 1.3 団体の絞り込み

- 一覧・詳細・編集・削除は**必ず団体 ID で絞る**。Repository のメソッド名に `DantaiId` を入れる（`findByIdAndDantaiId` など）
- 他団体の ID を URL に入れられても見えないように、1 件取得は `findByIdAndDantaiId(id, login.getDantaiId())`。取れなければ 404
- 登録するときの団体 ID はフォームからではなく `login.getDantaiId()` から入れる

### 1.4 フラッシュメッセージとエラー

基本設計 8 章のとおり。追加分だけ:

| タイミング | メッセージ |
|:---:|:---:|
| 削除拒否（里親） | 個体またはイベントに紐づいているため削除できません |
| 削除拒否（スタッフ本人） | 自分自身は削除できません |
| イベント完了 | イベントを完了にしました |

| エラー | 表示 |
|---|---|
| 存在しない ID・他団体の ID | 404「指定されたデータは存在しません」 |
| 権限がない | 403「この操作を行う権限がありません」 |
| 入力エラー | 同じフォームを再表示し、上部に項目ごとのメッセージ |
| それ以外 | 500「システムエラーが発生しました」 |



### 1.6 標準画面遷移（個体・里親・イベント・スタッフ共通）

ヘッダー: ログイン後の全画面で表示。トップ ／ 個体一覧 ／ 里親一覧 ／ イベント ／ スタッフ一覧 ／ ログアウト（POST フォーム）。<br>右端にログイン中の団体名と名前。

| 遷移元 | 操作 | 遷移先 |

### 3.2 機能（F-05 〜 F-11）

#### F-05 GET /animal（animalController#list）
1. `AnimalSearchForm`（species,status,name。すべて任意）を受ける
2. `animalService.search(login.getDantaiId(), form)` → `animalRepository.search(dantaiId, species, sex, status)`（`@Query` で `(:species is null or a.species = :species)` の形。並びは id 降順）
3. Model: `animalList`、`searchForm`、`speciesList`、`sexList`、`statusList` → animal/list.jsp

#### F-06 GET /animal/{id}（AnimalController#detail）
1. `animalService.findById(id, login.getDantaiId())` → `findByIdAndDantaiId`、空なら 404
2. `events` = `eventRepository.findByAnimalIdOrderByEventDateDescEventTimeDesc(id)`
3. Model: `animal`、`events` → animal/detail.jsp

## 4. イベント管理

### 4.1 画面（S-7 〜 S-010）

#### S-7 イベント一覧（event/list.jsp）

月間カレンダー形式でイベント予定一覧を表示する。

カレンダー内には登録されているイベントをイベントバーとして表示する。
イベント種別に応じてバーの色を分け、視認性を高める。

- 初期表示は現在年月のカレンダー表示
- 「前月」「次月」をクリックすると表示月を切り替え可能
- 同日に複数イベントが存在する場合は縦に並べて表示する


カレンダー内のイベントバーをクリックすると、画面右側にイベント概要ペインを表示する
- イベント概要ペイン右下にはイベント対応状況を示す
- 「対応済スタンプ欄」を表示する。
- イベントが未対応の場合はスタンプ欄を空欄で表示する
- ユーザーが空欄のスタンプ欄をクリックすると、イベントを対応済に更新し、肉球の「済」スタンプを表示する
- 一度対応済にしたイベント情報は通常のスタンプクリックでは未対応に戻さない
- 対応済のイベントはイベント一覧・イベント詳細・個体詳細・里親詳細・スタッフ詳細の関連イベント表示表示でも同じ対応済状態を反映する
- 概要ペイン右下に編集リンクアイコンを表示し、イベント編集ページに遷移できるようにする

#### S-17 スタッフ編集・S-18 スタッフ新規登録（staff/form.jsp 共用）

![スタッフフォーム](img/page_detail/s-17.png)

`<form:form modelAttribute="staffForm" method="post" enctype="multipart/form-data">`,`${mode}` が `new` / `edit`。

|項目|name|タグ・型|必須|チェック|エラーメッセージ|
|---|---|---|:---:|---|---|
|ログインID|loginId|new: text, maxlength=30|new: ○|Form: `@Pattern("^$\|^[a-zA-Z0-9]{4,30}$")`。Service（new）: 空・重複|ログインIDを入力してください / ログインIDは半角英数字4〜30文字で入力してください / 既に登録済みのログインIDです|
|パスワード|password|password, maxlength=72|new: ○|Form: `@Pattern("^$\|^.{8,72}$")`。Service: new は空不可、edit は空なら変更なし|パスワードを入力してください / パスワードは8〜72文字で入力してください|
|名前|name|text, maxlength=30|○|`@NotBlank @Size(max=30)`|名前を入力してください / 名前は30文字以内で入力してください|
|ふりがな|furigana|text, maxlength=30|○|`@NotBlank @Size(max=30)`|ふりがなを入力してください / ふりがなは30文字以内で入力してください|
|性別|gender|radio（男 / 女 / その他）|○|`@NotNull`|性別を選択してください|
|年齢| — |edit のみ表示（`birthday` から計算）|||入力項目ではない|
|生年月日|birthday|date|○|`@NotNull @Past`|生年月日を入力してください / 過去の日付を指定してください|
|住所|address|text, maxlength=100||`@Size(max=100)`|住所は100文字以内で入力してください|
|電話番号|phoneNumber|tel, maxlength=20|○|`@NotBlank @Size(max=20) @Pattern("^$\|^[0-9-]+$")`|電話番号を入力してください / 電話番号は数字とハイフンで入力してください|
|メールアドレス|email|email, maxlength=255||`@Size(max=255) @Email`|メールアドレスの形式が正しくありません|
|登録日| — |edit のみ表示（`created_at`）|||入力項目ではない|
|ユーザー種別|roleId|select（`userTypes`）|○|`@NotNull`。Service で `userTypeRepository.findById` が空なら rejectValue|ユーザー種別を選択してください / ユーザー種別の指定が不正です|
|特記事項|notes|textarea||`@Size(max=2000)`|2000文字以内で入力してください|

- 団体ID・登録者ID・更新者ID・登録日時・更新日時は画面から受け取らず、Service が `login` から設定する。
- `address` `email` `notes` が空文字のときは、Service で `null` に変換して保存する。
- ユーザー種別は管理ユーザーだけが変更できる。常勤スタッフが編集するときは、現在の値を表示のみにして `<form:hidden path="roleId"/>` で送る。Service は管理ユーザー以外の `roleId` を無視する。
- 編集で自分自身のユーザー種別は変更できない（ログイン中のセッションにロールが入っているため、変更が反映されなくなる）。

|キャンセル|new → S-15、edit → S-16|
