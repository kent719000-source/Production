## 1. 共通仕様

### 1.1 この文書の読み方

- 画面は `S-xx`（基本設計 1 章「画面一覧」の No）。例: S-03 個体一覧
- 機能は `F-xx`（基本設計 4 章「URL 設計」の No）。例: F-05 GET /kotai

### 1.2 ログインと権限

- ログインは Spring Security に任せる（Controller は書かない）。ログイン ID とパスワードで staff テーブルを検索し、パスワードは BCrypt で照合
- ログインしたら「自分の ID・団体 ID・権限」がセッションに入る。Controller では `@AuthenticationPrincipal LoginUser login` で受け取る
- 権限は基本設計 4 章のとおり。GET はボランティア以上、POST は常勤スタッフ以上、`/staff/new` だけ管理ユーザー
- 画面のボタン（新規登録・編集・削除・完了）は `<sec:authorize access="hasAnyRole('ADMIN','STAFF')">` で囲んでボランティアには見せない

### 1.3 団体の絞り込み

- 一覧・詳細・編集・削除は**必ず団体 ID で絞る**。Repository のメソッド名に `DantaiId` を入れる（`findByIdAndDantaiId` など）
- 他団体の ID を URL に入れられても見えないように、1 件取得は `findByIdAndDantaiId(id, login.getDantaiId())`。取れなければ 404
- 登録するときの団体 ID はフォームからではなく `login.getDantaiId()` から入れる

### 1.4 フラッシュメッセージとエラー

基本設計 8 章のとおり。追加分だけ:

| タイミング | メッセージ |
|:---:|:---:|
| 削除拒否（里親） | 個体またはイベントに紐づいているため削除できません |
| 削除拒否（スタッフ本人） | 自分自身は削除できません |
| イベント完了 | イベントを完了にしました |

| エラー | 表示 |
|---|---|
| 存在しない ID・他団体の ID | 404「指定されたデータは存在しません」 |
| 権限がない | 403「この操作を行う権限がありません」 |
| 入力エラー | 同じフォームを再表示し、上部に項目ごとのメッセージ |
| それ以外 | 500「システムエラーが発生しました」 |



### 1.6 標準画面遷移（個体・里親・イベント・スタッフ共通）

ヘッダー: ログイン後の全画面で表示。トップ ／ 個体一覧 ／ 里親一覧 ／ イベント ／ スタッフ一覧 ／ ログアウト（POST フォーム）。<br>右端にログイン中の団体名と名前。

| 遷移元 | 操作 | 遷移先 |
|:---:|:---:|:---:|
| 一覧 | 「新規登録」 | 新規登録画面（GET /xxx/new） |
| 一覧 | 行・カードをクリック | 詳細（GET /xxx/{id}） |
| 詳細 | 「編集」 | 編集画面（GET /xxx/{id}/edit） |
| 詳細 | 「削除」 | 確認 → POST /xxx/{id}/delete → 一覧へ。フラッシュ「〇〇を削除しました」 |
| 新規登録 | 「登録」 | POST /xxx/new → 詳細へ。フラッシュ「〇〇新規登録が完了しました」 |
| 編集 | 「更新」 | POST /xxx/{id}/edit → 詳細へ。フラッシュ「〇〇を編集しました」 |
| 新規登録・編集 | 入力エラー | 同じフォームを再表示 |
| 新規登録・編集 | 「キャンセル」 | 新規 → 一覧、編集 → 詳細 |
| どの画面でも | 存在しない id・他団体の id | 404 ページ |
| どの画面でも | 権限の無い URL | 403 ページ |
| 全画面 | ヘッダー | 各一覧・トップへ。ログアウト → /login?logout |

各機能の章では、この表と**違うところだけ**書く。


### 1.7 命名

| 対象 | 規則 | 例 |
|---|---|---|
| Controller | `XxxController`。ハンドラメソッド（URL 1 本に 1 つ）の名前は全機能で `list` `newForm` `create` `detail` `editForm` `update` `delete` に揃える。処理は Service に書き、Controller は受け取り・Service 呼び出し・JSP 返却だけ | `KotaiController` |
| Service / Repository / Entity / Form | `XxxService` `XxxRepository` `Xxx` `XxxForm` | `KotaiService` |
| JSP | `views/xxx/list.jsp` `detail.jsp` `form.jsp`（新規と編集で共用） | `kotai/form.jsp` |
| テーブル | 基本設計 3 章のまま（ローマ字・単数・小文字） | `kotai` `satooya` `event_type` |
| DB の列 | snake_case | `login_id` `dantai_id` |
| Entity ↔ テーブル | テーブル名をパスカルケースに。列名は snake_case → キャメルケース | `kotai` → `Kotai`、`phone_number` → `phoneNumber` |
| Java の変数 | キャメルケース。Entity 1 件はクラス名の小文字、複数は `xxxList` | `Kotai kotai`、`List<Kotai> kotaiList` |
| Model に入れる名前 | 1 件は `xxx`、一覧は `xxxList`、フォームは `xxxForm`、プルダウンの選択肢は複数形 | `kotai`、`kotaiList`、`kotaiForm`、`breeds`、`satooyas` |
| JSP のループ変数 | 頭文字 1 文字。画面の冒頭で `<c:forEach var="k" items="${kotaiList}">` を宣言 | `k`（個体）、`s`（里親・スタッフ）、`e`（イベント） |
| URL パラメータ・フォームの name | Form のフィールド名と同じ（キャメルケース） | `intakeDate`、`breedId` |
| enum の値 | DB の日本語値と同名 | `Status.保護中`、`Sex.オス` |

## 2. 個体管理

### 2.1 画面（S-03 〜 S-06）

#### S-03 個体一覧（kotai/list.jsp）
カード形式で個体の一覧を表示する。ホバリングで分かりやすくする。

- 絞り込み:保護状況(保護中(譲渡可)、保護中(譲渡不可)、トライアル中、入院中、譲渡済、返還、移管、死亡)、犬・猫

各カードの表示項目は以下の通り

|表示項目|内容|備考|
|---|---|---|
|写真|`<img src="/uploads/${k.imagePath}">`、無ければプレースホルダ||
|名前|`${k.name}`| カード全体を `<a href="/kotai/${k.id}">`|
|犬猫|`${k.species}`||
|性別|`${k.sex}`||
|年齢|`${k.age}`||
|品種|`${k.breed}`||
|保護状況|`${k.status}`||

|操作|権限|遷移先|
|---|:---:|---|
|新規登録リンク|S|S-06|
|カードクリック|V|S-04|
|検索ボタン|V|S-03（条件つき）|

#### S-04 個体詳細（kotai/detail.jsp）
|表示項目|内容|
|---|---|
|写真|大きめに1枚|
|基本|名前・犬猫・性別・品種・年齢・誕生日（推定）・保護日・保護場所と方法（intake_type）・保護状況|
|里親|保護状況がトライアル中・譲渡済のとき `${kotai.satooya.name}` を `/satooya/{id}` へのリンクで。それ以外は表示しない|
|医療|避妊去勢（済/未）・混合ワクチン（済/未）・狂犬病ワクチン（済/未。猫は「対象外」）・マイクロチップ番号 |
|特記事項|健康に関する特記事項・その他の特記事項`<c:out>` + `white-space: pre-wrap` |
|イベント一覧|この個体に関連するイベントを日付の降順で（日付・時刻・種別・場所・済/未）行は `/event/{id}`へのリンク 0件なら「イベントはありません」|

|削除ボタン|S|確認「紐づくイベントと写真も削除されます。本当に削除しますか？」→ F-11 |
|一覧へ戻る|V|S-03|

### 2.2 機能（F-05 〜 F-11）

#### F-05 GET /kotai（KotaiController#list）
1. `KotaiSearchForm`（species, sex, status。すべて任意）を受ける
2. `kotaiService.search(login.getDantaiId(), form)` → `kotaiRepository.search(dantaiId, species, sex, status)`（`@Query` で `(:species is null or k.species = :species)` の形。並びは id 降順）
3. Model: `kotaiList`、`searchForm`、`speciesList`、`sexList`、`statusList` → kotai/list.jsp

#### F-08 GET /kotai/{id}（KotaiController#detail）
1. `kotaiService.findById(id, login.getDantaiId())` → `findByIdAndDantaiId`、空なら 404
2. `events` = `eventRepository.findByKotaiIdOrderByEventDateDescEventTimeDesc(id)`
3. Model: `kotai`、`events` → kotai/detail.jsp
