## 1. 共通仕様

### 1.1 この文書の読み方

- **画面ID `S-xx`** は基本設計 1 章「画面一覧」の No（S-01 ログイン 〜 S-19 エラー）
- **機能ID `F-xx`** は基本設計 4 章「URL設計」の No（F-01 GET / 〜 F-33 POST /staff/{id}/delete）
- 2〜5 章は機能ごとに「画面 → 機能 → クラス」の順。画面の節に入力チェックを、機能の節の分岐にエラー時の動きを書く。共通のエラー（403 / 404 / 500）は 1.8
- 標準の CRUD 遷移は 1.11 に1回だけ書く。各機能の章は**標準からの差分だけ**書く

### 1.2 認証（F-02 〜 F-04）

| 項目 | 決め |
|---|---|
| 方式 | Spring Security のフォームログイン。Controller は書かない |
| 設定 | `SecurityConfig`: `loginPage("/login")`、`loginProcessingUrl("/login")`、`usernameParameter("loginId")`、`passwordParameter("password")`、`defaultSuccessUrl("/", true)`、`failureUrl("/login?error")`、`logoutUrl("/logout")`、`logoutSuccessUrl("/login?logout")` |
| パスワード | `BCryptPasswordEncoder`。`staff.password_hash` に保存。初期データもハッシュ済みの値を書く |
| ユーザー検索 | `LoginUserDetailsService implements UserDetailsService`。`staffRepository.findByLoginId(loginId)`。無ければ `UsernameNotFoundException` |
| セッションに入る物 | `LoginUser implements UserDetails`: `id`、`dantaiId`、`dantaiName`、`name`、`role`（enum Role） |
| ロールの決め方 | `staff.role_id` → `user_type.code`（`ADMIN` / `STAFF` / `VOLUNTEER`）。`getAuthorities()` は `ROLE_` + code の1件 |
| Controller での受け取り | `@AuthenticationPrincipal LoginUser login`。団体IDは常に `login.getDantaiId()` から取る |
| CSRF | Security 標準。POST の全フォームに `<sec:csrfInput/>`。無いと 403 |
| セッション | `server.servlet.session.timeout=8h`。ログイン成功時のセッション再生成は Security が自動 |

| F | URL | 処理 |
|:---:|---|---|
| F-02 | GET /login | `LoginController#login`。ログイン済みなら `redirect:/`。それ以外は login.jsp。`?error` で「ログインに失敗しました」、`?logout` で「ログアウトしました」を JSP が表示 |
| F-03 | POST /login | Security。ログインIDで staff を検索 → BCrypt 照合 → 成功で / へ、失敗で /login?error へ |
| F-04 | POST /logout | Security。セッション破棄 → /login?logout |

### 1.3 権限

`SecurityConfig` の `authorizeHttpRequests` に**上から順に**書く（先に書いた行が勝つ）。

| 順 | パターン | 許可 |
|:---:|---|---|
| 1 | `/login`、`/css/**`、`/js/**`、`/img/**`、`/error/**` | 全員 |
| 2 | `/staff/new` | ADMIN |
| 3 | `POST /**` | ADMIN、STAFF |
| 4 | それ以外 | ログイン済み全員（`authenticated`） |

| タイミング | メッセージ |
|---|---|
| ログイン失敗 | ログインに失敗しました |
| ログアウト | ログアウトしました |
| 新規登録成功 | 〇〇新規登録が完了しました |

### 1.5 エラー処理

| エラー | 発生条件 | HTTP | 捕まえる場所 | 表示 |
|---|---|:---:|---|---|
| 未ログイン | 認証なしで保護 URL | 302 | Security → /login | ログイン画面 |
| 権限なし・CSRF 不一致 | ロール不足、`<sec:csrfInput/>` 漏れ | 403 | `accessDeniedPage("/error/403")` → `ErrorPageController#forbidden` | error/403.jsp「この操作を行う権限がありません」 |
| データなし | id が無い、他団体の id | 404 | Service が `NotFoundException` → `GlobalExceptionHandler#notFound`（`@ExceptionHandler` + `@ResponseStatus(NOT_FOUND)`） | error/404.jsp「指定されたデータは存在しません」 |
| 入力エラー | Bean Validation・Service の追加チェック | 200 | 各 Controller が `BindingResult.hasErrors()` でフォーム再表示 | フォーム上部に項目ごとのメッセージ |
| ファイルサイズ超過 | 5MB 超 | 302 | `GlobalExceptionHandler#tooLarge`（`MaxUploadSizeExceededException`）→ フラッシュ → `Referer` へ | ファイルは 5MB 以下にしてください |
| システムエラー | DB 接続失敗など | 500 | `GlobalExceptionHandler#other`（`Exception`）→ ログ出力 | error/500.jsp「システムエラーが発生しました」 |

`NotFoundException` は `RuntimeException` を継承した空クラス。Service は `findByIdAndDantaiId(...).orElseThrow(NotFoundException::new)` と書く。

### 1.6 標準画面遷移（個体・里親・イベント・スタッフ共通）

ヘッダー: ログイン後の全画面で表示。トップ ／ 個体一覧 ／ 里親一覧 ／ イベント ／ スタッフ一覧 ／ ログアウト（POST フォーム）。右端にログイン中の団体名と名前。

| 遷移元 | 操作 | 遷移先 |
|:---|:---|:---|
| 一覧 | 「新規登録」リンク（S 以上。スタッフの新規登録は A） | 新規登録（GET /xxx/new） |
| 一覧 | カード／行クリック | 詳細（GET /xxx/{id}） |
| 一覧 | 絞り込みフォームの「検索」 | 同じ一覧（GET /xxx?条件）。条件はフォームに残る |
| 詳細 | 「編集」リンク（S 以上） | 編集（GET /xxx/{id}/edit） |
| 詳細 | 「削除」ボタン（S 以上） | 確認ダイアログ → POST /xxx/{id}/delete → 一覧へリダイレクト、フラッシュ「〇〇を削除しました」 |
| 詳細 | 削除が拒否されたとき（里親・スタッフ本人） | 詳細へリダイレクト、拒否のフラッシュ |
| 新規登録 | 「登録」ボタン | POST /xxx/new → 詳細へリダイレクト、フラッシュ「〇〇新規登録が完了しました」（イベントだけ /event へ） |
| 編集 | 「更新」ボタン | POST /xxx/{id}/edit → 詳細へリダイレクト、フラッシュ「〇〇を編集しました」 |
| 新規登録／編集 | 入力エラー | 同じフォームを再表示（リダイレクトなし、入力値は保持） |
| 新規登録／編集 | 「キャンセル」リンク | 新規 → 一覧、編集 → 詳細 |
| どの画面でも | 存在しない id・他団体の id | 404 ページ |
| どの画面でも | 権限の無い URL | 403 ページ |
| 全画面 | ヘッダー | 各一覧・トップへ。ログアウト → /login?logout |

### 2.2 機能（F-05 〜 F-11）

#### F-05 GET /kotai（KotaiController#list）
1. `KotaiSearchForm`（species, sex, status。すべて任意）を受ける
2. `kotaiService.search(login.getDantaiId(), form)` → `kotaiRepository.search(dantaiId, species, sex, status)`（`@Query` で `(:species is null or k.species = :species)` の形。並びは id 降順）
3. Model: `kotaiList`、`searchForm`、`speciesList`、`sexList`、`statusList` → kotai/list.jsp

#### F-08 GET /kotai/{id}（KotaiController#detail）
1. `kotaiService.findById(id, login.getDantaiId())` → `findByIdAndDantaiId`、空なら 404
2. `events` = `eventRepository.findByKotaiIdOrderByEventDateDescEventTimeDesc(id)`
3. Model: `kotai`、`events` → kotai/detail.jsp
