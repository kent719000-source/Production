## 1. 共通仕様

### 1.1 この文書の読み方

- 画面は `S-xx`（基本設計 1 章「画面一覧」の No）。例: S-03 個体一覧
- 機能は `F-xx`（基本設計 3 章「URL 設計」の No）。例: F-05 GET /animal
- 各章は「画面 → 機能」の順。画面はカンプの画像と表で説明。
- フォームの表の「name」はFormクラスのフィールド名（=`<form:input path>` の値）。「型」の`text(2000)`は`<input type="text" maxlength="2000">`の意味

### 1.2 ログインと権限

- ログインはSpring Securityに任せる（POST /loginと POST /logoutのControllerは書かない）
- ログインしたら`LoginUser`（id・団体ID・名前・ロール）がセッションに入る。Controllerでは `@AuthenticationPrincipal LoginUser loginUser`で受け取る。団体IDは常に`loginUser.getOrganizationId()`
- 権限は基本設計3章のとおり。**GETはV、POSTはS、削除と `/staff/new`はA**
- 画面のボタンは新規登録・編集・完了を`<sec:authorize access="hasAnyRole('ADMIN','STAFF')">`、削除とスタッフ新規登録を`<sec:authorize access="hasRole('ADMIN')">`で囲む

### 1.3 団体の絞り込み

基本設計8章のとおり。1件取得は必ず `findByIdAndOrganizationId(id, loginUser.getOrganizationId())`、空なら 404。登録するときの団体IDは `loginUser` から。

### 1.4 フラッシュメッセージとエラー

基本設計 8 章のとおり。

### 1.5 入力チェックの書き方

- Formに`@NotBlank` `@Size` `@NotNull` `@Email` `@Pattern` `@Past`などを付け、メッセージはアノテーションに直接書く
- Controllerは`@Valid XxxForm form, BindingResult result`で受け、`result.hasErrors()`なら同じフォームを再表示（プルダウンの選択肢をModelに入れ直す）
- アノテーションで書けないチェック（ログインID重複、里親の必須条件、写真の種類）はServiceで判定し`result.rejectValue()`で乗せる
- 日付は`<input type="date">`+`LocalDate`+`@DateTimeFormat(iso = ISO.DATE)`
- プルダウン・ラジオはenumの定数名を送り、表示は`label`
- 任意の文字列項目が空文字ならServiceで`null`にして保存

### 1.6 標準画面遷移（個体・里親・イベント・スタッフ共通）

ヘッダー: ログイン後の全画面で表示。トップ / 個体一覧 / 里親一覧 / イベント / スタッフ一覧  <br>右端にログイン中の団体名と名前 / ログアウト（POST フォーム）

|遷移元|操作|遷移先|
|:---:|:---:|:---:|
|一覧|「新規登録」| 新規登録画面（GET /xxx/new）|
|一覧| 行・カードをクリック | 詳細（GET /xxx/{id}）|
|詳細|「編集」|編集画面（GET /xxx/{id}/edit）|
|詳細|「削除」|確認 → POST /xxx/{id}/delete → 一覧へ。フラッシュ「〇〇を削除しました」|
|新規登録|「登録」|POST/xxx/new → 詳細へ。フラッシュ「〇〇新規登録が完了しました」|
|編集|「更新」|POST/xxx/{id}/edit → 詳細へ。フラッシュ「〇〇を編集しました」|
|新規登録・編集| 入力エラー | 同じフォームを再表示 |
|新規登録・編集| 「キャンセル」 | 新規 → 一覧、編集 → 詳細 |


各機能の章では、この表と**違うところだけ**書く。


### 1.7 命名

基本設計8章のとおり。追加分:Serviceのメソッドは`search` `find` `create` `update` `delete`（イベントだけ `complete`）。検索条件は `XxxSearchForm`、Model名`searchForm`。BOOLEANのフィールドは`is_`を付けない（`neutered`。列名は `@Column(name = "is_neutered")`）。

### 1.8 共通部品

- `jsp/common/header.jspf`:taglib宣言、ナビ、ログアウトの`<form:form action="/logout" method="post">`、フラッシュの表示
- `static/js/confirm.js`: `confirmSubmit(msg)`。削除・完了の form の `onsubmit`で呼ぶ
- `static/img/placeholder-dog.png` `placeholder-cat.png`: 写真が無い個体に犬猫で出し分け
- 年齢はEntityの`@Transient getAge()`で誕生日から計算。無ければ「不明」

### 3.2 機能（F-05 〜 F-11）

#### F-05 GET /animal（AnimalController#list）
1. `AnimalSearchForm`（species,status,name。すべて任意）を受ける
2. `animalService.search(loginUser.getOrganizationId(), form)` → `animalRepository.search(organizationId, species, sex, status)`（`@Query` で `(:species is null or a.species = :species)` の形。並びは id 降順）
3. Model: `animalList`、`searchForm`、`speciesList`、`sexList`、`statusList` → animal/list.jsp

#### F-06 GET /animal/{id}（AnimalController#detail）
1. `animalService.findById(id, loginUser.getOrganizationId())` → `findByIdAndDantaiId`、空なら 404
2. `events` = `eventRepository.findByAnimalIdOrderByEventDateDescEventTimeDesc(id)`
3. Model: `animal`、`events` → animal/detail.jsp

#### F-07 GET /animal/new (AnimalController#newForm)
1. 空の入力フォームを用意する。
　 `new AnimalForm()`
2. 種別・性別・避妊/去勢・混合ワクチン・狂犬病ワクチンのラジオボタンの選択肢を用意する。
　 `Species.values()`(犬 / 猫 。表示は`label`)
　 `Sex.values()`(オス / メス / 不明。表示は`label`)
　 `IsNeutered.values()`(済 / 未 / 不明。表示は`label`)
　 `ComboVaccine.values()`(済 / 未 / 不明。表示は`label`)
　 `RabiesVaccine.values()`(済 / 未 / 不明。表示は`label`)
3. 新規登録モードで画面を表示する。
　 Model: `AnimalForm`、`sexList`、`mode`="new" → Animal/form.jsp
- DB へのアクセスはないため、団体IDの絞り込みは不要。
- 権限はSecurityConfigで制御(ボランティアがURLを直接開いたら403)

#### F-08 POST /animal/new (AnimalController#create)
1. 入力値を`AnimalForm`で受け取り、入力チェックを行う。
　 `@Validated AnimalForm animalForm,BindingResult result`
2. 入力エラーがあれば、同じフォームを再表示する。（リダイレクトしない）
　　Model: `animalForm`（入力値とエラー）、`sexList`、`mode`="new" → animal/form.jsp
3. エラーがなければ個体を登録する。団体はフォームからではなくログイン情報から設定する。
　　`animalService.create(animalForm,loginUser.getOrganizationId())`
　 → Formの値を`Animal`に詰め替え、`breed_id``birthday``adopter_id``microchip_no``health_notes``notes`が空文字なら null に変換。
　 → `organization` = `organizationRepository.getReferenceById(organizationId)`
　 → `animalRepository.save(animal)`、登録された `id` を返す。
4. フラッシュメッセージを設定し、登録した個体の詳細へリダイレクトする。
　 フラッシュ「個体の新規登録が完了しました」→ `redirect:/animal/{id}`(F-06)

#### F-09 GET /animal/{id}/edit (AnimalController#editForm)
1. パス変数 `id`(Integer) を受ける。
2. 編集する個体を取得する。他団体のデータを編集させないよう団体IDも条件に含める。
　 `animalService.getEditForm(id, loginUser.getOrganizationId())` → `animalRepository.findByIdAndOrganizationId(id, organizationId)`。空なら`ResponseStatusException(HttpStatus.NOT_FOUND)`
3. 取得した`Animal`の値を`AnimalForm`に詰めて返す。(null の項目は空欄表示)
4. 編集モードで画面を表示する。
　 Model: `animalForm` (現在値入り)、`animalId`、`sexList`、`mode`="edit" → animal/form.jsp
- 権限はSecurityConfigで制御（ボランティアは403）

#### F-10 POST /animal/{id}/edit (AnimalController#update)
1. パス変数 `id`（Integer）と入力値`AnimalForm`を受け取り、入力チェックを行う。
　 `@PathVariable Integer id, @Validated AnimalForm animalForm, BindingResult result`
2. 入力エラーがあれば、同じフォームを再表示する(リダイレクトしない)
　 Model: `animalForm`（入力値とエラー）、`animalId`、`sexList`、`mode`="edit" → animal/form.jsp
3. エラーがなければ個体を更新する。更新前に団体ID付きで取り直す。
　 `animalService.update(id, adopterForm, loginUser.getOrganizationId())`
　 → `animalRepository.findByIdAndOrganizationId(id, organizationId)`。空なら`ResponseStatusException(HttpStatus.NOT_FOUND)`
　 → 取得した`Animal` に Form の値を上書き。`address``email``notes`が空文字なら null に変換。
　 → `organization` `createdAt` は変更しない
　 → `adopterRepository.save(adopter)`
4. フラッシュメッセージを設定し、個体詳細へリダイレクトする
　 フラッシュ「個体を編集しました」→ `redirect:/animal/{id}`(F-06)

#### F-11 POST /animal/{id}/delete (AnimalController#delete)
1. パス変数 `id` (Integer)を受ける。
2. 削除する個体を取得する。他団体のデータを削除させないよう団体IDも条件に含める。
　 `animalService.delete(id, loginUser.getOrganizationId())` → `animalRepository.findByIdAndOrganizationId(id, organizationId)`。空なら`ResponseStatusException(HttpStatus.NOT_FOUND)`
3. 紐づく里親・イベントがあるか確認する
　 `adopterRepository.existsByOrganizationIdAndAdopterId(organizationId, id)`
 　`eventRepository.existsByOrganizationIdAndAdopterId(organizationId, id)`
　 → フラッシュ「紐づくイベントと写真も削除されます。本当に削除しますか？」
4. 紐づきがなければ削除し、true を返す
　 `animalRepository.delete(animal)`
　 → フラッシュ「個体を削除しました」→ `redirect:/animal`(F-05)
- 権限は SecurityConfigで制御（管理ユーザー以外は403）
- 削除ボタン押下時は confirm.js で「本当に削除しますか？」を表示（F-11）

## 4. イベント管理

### 4.1 画面（S-07 〜 S-10）

#### S-07 イベント一覧（event/calendar.jsp）

![イベント一覧](img/page_detail/s-07.png)

画面の動き
- 月間カレンダーでその月のイベントを表示する。初期表示は今月。
- ◁▷で前月・次月に切り替える（`/event?year=&month=`）
- 同じ日に複数のイベントがあれば縦に並べる
- イベントバーは未対応と対応済で色を分ける。
- バーをクリックすると、概要ペインにそのイベントを表示する。
- 対応済のスタンプを押すと、確認の上未対応に戻す（個体の情報は戻らないのでポップアップで表示する）

カレンダー表示項目

|表示項目|内容|備考|
|---|---|---|
|年月|年`${calendar.year}`、月`${calendar.month}`|現在表示中の年月|
|日付|`${d.day}`|月間カレンダー形式|
|イベントバー|個体名`${e.animal.name}`、`${e.eventType.name}`|dが持つイベント一覧をループ（e）|


概要ペイン表示項目
ペインの値はすべてバーのdata属性からJSで表示する。文字はすべて `fn:escapeXml` でエスケープする。

|表示項目|内容|備考|
|---|---|---|
|基本|日付、時刻、個体名、種別、場所、費用|時刻・場所・費用は任意　無ければ表示しない|
|里親|`${e.adopter.name}`|里親が紐づいているときだけ表示|
|特記事項|  `${e.notes}`（改行を保って表示）|`white-space: pre-wrap`|
|対応状況|未/済|未対応なら空のスタンプ欄、済なら済スタンプ|

|操作|権限|遷移先|
|---|:---:|---|
|新規登録ボタン|S|S-09|
|イベントバークリック|V|概要ペインに表示（画面遷移なし）|
|◁▷|V|S-07（前月・次月の年月つき）|
|スタンプ欄のクリック（未対応のとき）|S|確認「イベントを完了にしますか？」→ F-18|
|スタンプ欄のクリック（対応済のとき）|S|確認「未対応に戻しますか？個体の情報は元に戻りません」 → （基本設計書URL設計見直し）|
|詳細リンク|V|S-08|
|編集リンク|S|S-10|

選択したイベントの詳細を表示する。

### 4.2 機能（F-12 〜 F-19）

#### F-12 GET /event（EventController#list）
1. 表示する年月 `year` `month`（Integer。どちらも任意）を受ける。

3. Model: `calendar` → event/calendar.jsp

`EventCalendar`（カレンダー1か月分）

|month|int|表示中の月|
|prevYear / prevMonth|int|前月の年・月（◁ のリンク用）|
|nextYear / nextMonth|int|次月の年・月（▷ のリンク用）|
|weeks|`List<List<CalendarDay>>`|週のリスト。1週は日曜〜土曜の7日|

`CalendarDay`（カレンダー1マス分）

#### F-13 GET /event/{id}（EventController#detail）
1. パス変数 `id`（Integer）を受ける。
2. イベントを取得する。団体IDも条件に含める。

3. Model: `event` → event/detail.jsp
- 「一覧へ戻る」の年月は `${event.eventDate.year}` `${event.eventDate.monthValue}` から作る。

#### F-14 GET /event/new (EventController#newForm)
1. 空の入力フォームを用意する。
　 `new EventForm()`
2. プルダウンの選択肢を用意する。個体・里親は自団体のものだけ。
　 `eventService.findAnimalList(organizationId, null)` → `animalRepository.findByOrganizationIdAndStatusInOrderByIdDesc(organizationId, [保護中(譲渡可), 保護中(譲渡不可), トライアル中, 入院中])`
　 `eventService.findEventTypeList()` → `eventTypeRepository.findAll()`
　 `eventService.findAdopterList(organizationId)` → `adopterRepository.findByOrganizationIdOrderByIdDesc(organizationId)`
3. 新規登録モードで画面を表示する。
　 Model: `eventForm`、`animalList`、`eventTypeList`、`adopterList`、`mode`="new" → event/form.jsp
- 保護状況の定数名は、修正ポイント 2-1 で決まったものに置き換える。
- 権限はSecurityConfigで制御(ボランティアがURLを直接開いたら403)

#### F-15 POST /event/new (EventController#create)
1. 入力値を`EventForm`で受け取り、入力チェックを行う。
　 `@Validated EventForm eventForm, BindingResult result`
2. 入力エラーがあれば、同じフォームを再表示する。（リダイレクトしない）
　 Model: `eventForm`（入力値とエラー）、`animalList`、`eventTypeList`、`adopterList`、`mode`="new" → event/form.jsp
3. アノテーションで書けないチェックをしてから、イベントを登録する。団体はフォームからではなくログイン情報から設定する。
　 `eventService.create(eventForm, result, loginUser.getOrganizationId())`
　 → `animalRepository.findByIdAndOrganizationId(animalId, organizationId)`。空なら `result.rejectValue("animalId", ...)`
　 → `eventTypeRepository.findById(eventTypeId)`。空なら `result.rejectValue("eventTypeId", ...)`
　 → 種別の `code` が `TRIAL_START` `ADOPTION` で `adopterId` が空なら `result.rejectValue("adopterId", ...)`
　 → `adopterId` 指定時は `adopterRepository.findByIdAndOrganizationId(adopterId, organizationId)`。空なら `result.rejectValue("adopterId", ...)`
　 → エラーがあれば保存せずに戻る（Controller が 2. と同じく再表示）
　 → Formの値を`Event`に詰め替え、`place` `notes` が空文字なら null に変換。`done` は false、`staff` は null。
　 → `organization` = `organizationRepository.getReferenceById(organizationId)`
　 → `eventRepository.save(event)`、登録したイベントを返す。
4. フラッシュメッセージを設定し、登録したイベントの年月のカレンダーへリダイレクトする。
　 フラッシュ「イベント新規登録が完了しました」→ `redirect:/event?year={年}&month={月}`(F-12)

#### F-16 GET /event/{id}/edit (EventController#editForm)
1. パス変数 `id`(Integer) を受ける。
2. 編集するイベントを取得する。他団体のデータを編集させないよう団体IDも条件に含める。
　 `eventService.getEditForm(id, loginUser.getOrganizationId())` → `eventRepository.findByIdAndOrganizationId(id, organizationId)`。空なら`ResponseStatusException(HttpStatus.NOT_FOUND)`
3. 取得した`Event`の値を`EventForm`に詰めて返す。(null の項目は空欄表示)
　 `animalId` は `event.getAnimal().getId()`、`eventTypeId` は `event.getEventType().getId()`、`adopterId` は里親が無ければ null
4. プルダウンの選択肢を用意する。個体は現在の個体も含める。
　 `eventService.findAnimalList(organizationId, 現在の個体ID)`（現在の個体が4つの保護状況に入っていなければ、選択肢に追加する）
　 種別・里親は F-14 と同じ
5. 編集モードで画面を表示する。
　 Model: `eventForm` (現在値入り)、`eventId`、`animalList`、`eventTypeList`、`adopterList`、`mode`="edit" → event/form.jsp
- 権限はSecurityConfigで制御（ボランティアは403）

#### F-17 POST /event/{id}/edit (EventController#update)
1. パス変数 `id`（Integer）と入力値`EventForm`を受け取り、入力チェックを行う。
　 `@PathVariable Integer id, @Validated EventForm eventForm, BindingResult result`
2. 入力エラーがあれば、同じフォームを再表示する(リダイレクトしない)
　 Model: `eventForm`（入力値とエラー）、`eventId`、`animalList`、`eventTypeList`、`adopterList`、`mode`="edit" → event/form.jsp（選択肢は F-16 と同じ）
3. エラーがなければイベントを更新する。更新前に団体ID付きで取り直す。
　 `eventService.update(id, eventForm, result, loginUser.getOrganizationId())`
　 → `eventRepository.findByIdAndOrganizationId(id, organizationId)`。空なら`ResponseStatusException(HttpStatus.NOT_FOUND)`
　 → F-15 の 3. と同じチェック。エラーがあれば保存せずに戻る
　 → 取得した`Event` に Form の値を上書き。`place` `notes` が空文字なら null に変換。
　 → `organization` `done` `staff` `createdAt` は変更しない
　 → `eventRepository.save(event)`
4. フラッシュメッセージを設定し、イベント詳細へリダイレクトする
　 フラッシュ「イベントを編集しました」→ `redirect:/event/{id}`(F-13)

#### F-18 POST /event/{id}/complete (EventController#complete)
1. パス変数 `id` (Integer)を受ける。
2. イベントを完了にし、種別に応じて個体を更新する。
　 `eventService.complete(id, loginUser.getOrganizationId(), loginUser.getId())`
　 → `eventRepository.findByIdAndOrganizationId(id, organizationId)`。空なら`ResponseStatusException(HttpStatus.NOT_FOUND)`
　 → すでに対応済なら何もしない（二重クリックや、別の人が先に完了にした場合）
　 → `done` を true、`staff` を `staffRepository.getReferenceById(staffId)`（完了にした人）にする。
　 → 種別の `code` に応じて、紐づく個体を更新する（下の表）。
　 → `eventRepository.save(event)`、`animalRepository.save(animal)`
3. フラッシュメッセージを設定し、イベントの年月のカレンダーへリダイレクトする。
　 フラッシュ「イベントを完了にしました」→ `redirect:/event?year={年}&month={月}`(F-12)
- イベントと個体の更新は1つのトランザクション（Service の `@Transactional`）。途中で失敗したらどちらも更新されない。
- 権限は SecurityConfigで制御（ボランティアは403）
- スタンプ欄押下時は confirm.js で「イベントを完了にしますか？」を表示（S-07・S-08）

|種別 `code`|個体の更新|
|---|---|
|`COMBO_VACCINE`|`comboVaccine` を済|
|`RABIES_VACCINE`|`rabiesVaccine` を済|
|`NEUTERING`|`neutered` を済|
|`TRIAL_START`|`status` をトライアル中、`adopter` をイベントの里親に|
|`ADOPTION`|`status` を譲渡済、`adopter` をイベントの里親に|
|`HOSPITAL` `OTHER`|更新しない|

#### F-34 POST /event/{id}/uncomplete (EventController#uncomplete)
1. パス変数 `id` (Integer)を受ける。
2. イベントを未対応に戻す。
　 `eventService.uncomplete(id, loginUser.getOrganizationId())`
　 → `eventRepository.findByIdAndOrganizationId(id, organizationId)`。空なら`ResponseStatusException(HttpStatus.NOT_FOUND)`
　 → すでに未対応なら何もしない
　 → `done` を false、`staff` を null にする。個体は更新しない。
　 → `eventRepository.save(event)`
3. フラッシュメッセージを設定し、イベントの年月のカレンダーへリダイレクトする。
　 フラッシュ「イベントを未対応に戻しました」→ `redirect:/event?year={年}&month={月}`(F-12)
- 権限は SecurityConfigで制御（ボランティアは403）
- スタンプ欄押下時は confirm.js で「未対応に戻しますか？個体の情報は元に戻りません」を表示（S-07・S-08）

#### F-19 POST /event/{id}/delete (EventController#delete)
1. パス変数 `id` (Integer)を受ける。
2. 削除するイベントを取得する。他団体のデータを削除させないよう団体IDも条件に含める。
　 `eventService.delete(id, loginUser.getOrganizationId())` → `eventRepository.findByIdAndOrganizationId(id, organizationId)`。空なら`ResponseStatusException(HttpStatus.NOT_FOUND)`
3. 削除する。イベントに紐づくデータは無いので、紐づきの確認は不要。
　 `eventRepository.delete(event)`
　 → 個体は更新しない（完了済のイベントを削除しても、ワクチンなどは済のまま）
4. フラッシュメッセージを設定し、削除したイベントの年月のカレンダーへリダイレクトする。
　 フラッシュ「イベントを削除しました」→ `redirect:/event?year={年}&month={月}`(F-12)
- 権限は SecurityConfigで制御（管理ユーザー以外は403）
- 削除ボタン押下時は confirm.js で「本当に削除しますか？」を表示（S-08）

3. エラーがなければ里親を登録する。団体はフォームからではなくログイン情報から設定する。
　　`adopterService.create(adopterForm,loginUser.getOrganizationId())`
　 → Formの値を`Adopter`に詰め替え、`address``email``notes`が空文字なら null に変換。
　 → `organization` = `organizationRepository.getReferenceById(organizationId)`
　 → `adopterRepository.save(adopter)`、登録された `id` を返す。
4. フラッシュメッセージを設定し、登録した里親の詳細へリダイレクトする。
　 フラッシュ「里親新規登録が完了しました」→ `redirect:/adopter/{id}`(F-21)

#### F-24 GET /adopter/{id}/edit (AdopterController#editForm)
1. パス変数 `id`(Integer) を受ける。
2. 編集する里親を取得する。他団体のデータを編集させないよう団体IDも条件に含める。
　 `adopterService.getEditForm(id, loginUser.getOrganizationId())` → `adopterRepository.findByIdAndOrganizationId(id, organizationId)`。空なら`ResponseStatusException(HttpStatus.NOT_FOUND)`
3. 取得した`Adopter`の値を`AdopterForm`に詰めて返す。(null の項目は空欄表示)
4. 編集モードで画面を表示する。
　 Model: `adopterForm` (現在値入り)、`adopterId`、`genderList`、`mode`="edit" → adopter/form.jsp
- 権限はSecurityConfigで制御（ボランティアは403）

#### F-25 POST /adopter/{id}/edit (AdopterController#update)
1. パス変数 `id`（Integer）と入力値`AdopterForm`を受け取り、入力チェックを行う。
　 `@PathVariable Integer id, @Validated AdopterForm adopterForm, BindingResult result`
2. 入力エラーがあれば、同じフォームを再表示する(リダイレクトしない)
　 Model: `adopterForm`（入力値とエラー）、`adopterId`、`genderList`、`mode`="edit" → adopter/form.jsp
3. エラーがなければ里親を更新する。更新前に団体ID付きで取り直す。
　 `adopterService.update(id, adopterForm, loginUser.getOrganizationId())`
　 → `adopterRepository.findByIdAndOrganizationId(id, organizationId)`。空なら`ResponseStatusException(HttpStatus.NOT_FOUND)`
　 → 取得した`Adopter` に Form の値を上書き。`address``email``notes`が空文字なら null に変換。
　 → `organization` `createdAt` は変更しない
　 → `adopterRepository.save(adopter)`
4. フラッシュメッセージを設定し、里親詳細へリダイレクトする
　 フラッシュ「里親を編集しました」→ `redirect:/adopter/{id}`(F-21)

#### F-26 POST /adopter/{id}/delete (AdopterController#delete)
1. パス変数 `id` (Integer)を受ける。
2. 削除する里親を取得する。他団体のデータを削除させないよう団体IDも条件に含める。
　 `adopterService.delete(id, loginUser.getOrganizationId())` → `adopterRepository.findByIdAndOrganizationId(id, organizationId)`。空なら`ResponseStatusException(HttpStatus.NOT_FOUND)`
3. 紐づく個体・イベントがあるか確認する（個体は保護状況に関係なくすべて対象）
　 `animalRepository.existsByOrganizationIdAndAdopterId(organizationId, id)`
 　`eventRepository.existsByOrganizationIdAndAdopterId(organizationId, id)`
　 どちらかが true なら false を返す。
　 → フラッシュ「個体またはイベントに紐づいているため削除できません」→ `redirect:/adopter/{id}`(F-21)
4. 紐づきがなければ削除し、true を返す
　 `adopterRepository.delete(adopter)`
　 → フラッシュ「里親を削除しました」→ `redirect:/adopter`(F-20)
- 権限は SecurityConfigで制御（管理ユーザー以外は403）
- 削除ボタン押下時は confirm.js で「本当に削除しますか？」を表示（S-12）

## 7. エラー

#### S-19 エラー（error.jsp）

<br>
<a id="chapter8"></a>

Java のクラスは書かない。`server.error.whitelabel.enabled=false` にしておくと Spring Boot が 403 / 404 / 413 / 500 で `jsp/error.jsp` を表示する。`${status}` で文言を分ける。

|`${status}`|文言|
|:---:|---|
|403|この操作を行う権限がありません|
|404|指定されたデータは存在しません|
|413|ファイルは 5MB 以下にしてください|
|その他|システムエラーが発生しました|

- 404 は Service が `throw new ResponseStatusException(HttpStatus.NOT_FOUND)`
- 403 は Spring Security。生の `<form>` で POST しても（CSRF）403 になるので、POST は必ず `<form:form>`
- 土台を動かしたら、存在しない URL・V で POST・6MB の画像の 3 つを試して error.jsp が出ることを確かめる
