## 1. 共通仕様

### 1.1 この文書の読み方

- 画面は `S-xx`（基本設計1章「画面一覧」の No）。例: S-03 個体一覧
- 機能は `F-xx`（基本設計3章「URL設計」の No）。例: F-05 GET /animal。F-34（未対応に戻す）は詳細設計で追加した機能で、基本設計3章にはまだ載っていない
- 各章は「画面 → 機能」の順。画面はカンプの画像と表で説明。新規登録と編集は同じ JSP を共用するので、カンプは新規登録の1枚だけ載せる（編集は同じレイアウトに現在値が入る）
- フォームの表の「name」は Form クラスのフィールド名（= `<form:input path>` の値）。「タグ・型」の `text, maxlength=10` は `<input type="text" maxlength="10">` の意味

### 1.2 ログインと権限

- ログインは Spring Security に任せる（`POST /login` と `POST /logout` の Controller は書かない）
- ログインしたらセッションに入るのは Spring Security 標準の `User`（ログインIDとロール）だけ。`User` は `LoginUserDetailsService` が作り、ロールは `User.withUsername(...).roles(user_types.code)` で付ける（`roles()` が `ROLE_` を付けるので、自分で `ROLE_` を付けない。付けると `ROLE_ROLE_ADMIN` になって全員 403）
- `LoginUser` は `@Component` の窓口クラス。Controller に `private final LoginUser loginUser;` で注入して使う。呼ばれるたびに、ログインIDで staff を引き直して返す。`@AuthenticationPrincipal` は使わない。`loginUser.getId()` は無い（スタッフIDは `getStaffId()`）
  - `getOrganizationId()`（団体ID）・`getStaffId()`（スタッフID）・`getOrganizationName()`（団体名）・`getName()`（名前）・`getRole()`（`ADMIN` など）・`getUserTypeName()`（管理ユーザー など）・`isLoggedIn()`
  - 団体IDは常に `loginUser.getOrganizationId()`。ログインしていないときに呼ぶと例外になる
- 権限は基本設計3章のとおり。GETはV、POSTはS。ただし新規登録・編集のフォーム（`/xxx/new` `/xxx/{id}/edit`）はGETもS（ボランティアがURLを直接開いたら403）。削除・`/staff/new`・`/staff/{id}/edit`（GET・POST）はA
- `SecurityConfig` に必ず書く設定（書かないとログイン画面が出ない・ログインできない）
  - `.formLogin(...)` に `.loginPage("/login")` と `.usernameParameter("loginId")`。ログインIDの name が Spring Security の既定（`username`）ではなく `loginId` のため。パスワードは既定の `password` のまま
  - `.dispatcherTypeMatchers(DispatcherType.FORWARD, DispatcherType.ERROR).permitAll()`。JSP への転送と error.jsp の表示を通す（無いと、未ログインで `/login` を開いたときにリダイレクトが繰り返される）
  - `/login` `/css/**` `/js/**` `/img/**` は `permitAll()`（ログイン前でも画面とスタイルを出す）。写真の `/photos/**` はログイン必須のまま
  - `requestMatchers` は先に書いたものが優先されるので、範囲の狭いものから順に書く: `permitAll()` のもの → A（`/*/*/delete`、`/staff/new`、`/staff/*/edit`）→ S（`/*/new`、`/*/*/edit`、POST すべて）→ 残りはログイン必須。「GETはV」を先に書くと、ボランティアが登録・編集フォームを開けてしまう
  - 土台を動かしたら、未ログインでログイン画面が表示されること、正しいIDとパスワードでトップページへ進めること、ボランティアでログインしたときに編集・削除のボタンとスタンプ欄が出ず、代わりに対応状況が「未対応」「対応済」の文字で出ることを確かめる
- 画面のボタンは `<sec:authorize access="...">` で囲む。新規登録・編集・完了・未対応に戻すは `hasAnyRole('ADMIN','STAFF')`、削除とスタッフの新規登録・編集は `hasRole('ADMIN')`。ボランティアにはスタンプ欄の代わりに対応状況を文字で出す（`!hasAnyRole('ADMIN','STAFF')` で囲む。S-07・S-08）。`sec` のタグを使うには、pom.xml に `spring-security-taglibs` を足す

### 1.3 団体の絞り込み

基本設計8章のとおり。1件取得は必ず `findByIdAndOrganizationId(id, loginUser.getOrganizationId())`、空なら 404。登録するときの団体IDは `loginUser` から。

### 1.4 フラッシュメッセージとエラー

基本設計8章のとおり。

### 1.5 入力チェックの書き方

- Form に `@NotBlank` `@Size` `@NotNull` `@Email` `@Pattern` `@Past` `@PastOrPresent`などを付け、メッセージはアノテーションに直接書く
- 各章の表の `@Pattern("...")` は略記。実際は `@Pattern(regexp = "...", message = "...")` と書く。表の中の `\|` は Markdown の表を崩さないための書き方で、Java では `|` と書く
- Controller は `@Validated XxxForm xxxForm, BindingResult result` で受け、`result.hasErrors()` なら同じフォームを再表示（プルダウンの選択肢を Model に入れ直す）
- アノテーションで書けないチェック（ログインID重複、新規登録時のパスワード必須、里親の必須条件、プルダウンで選んだID（品種・個体・イベント種別・里親・ユーザー種別）の存在確認、写真の種類、犬の狂犬病ワクチン、猫の狂犬病ワクチンイベント、自分自身のユーザー種別の変更など）は Service で判定し `result.rejectValue()` で乗せる。エラーがあれば保存せずに戻る（戻り値があるメソッドは null を返す）。Controller は Service を呼んだあとでもう一度 `result.hasErrors()` を見て、エラーなら同じフォームを再表示する
- 日付は `<input type="date">` + `LocalDate` + `@DateTimeFormat(iso = ISO.DATE)`
- 時刻は `<input type="time">` + `LocalTime` + `@DateTimeFormat(pattern = "HH:mm")`
- 数値や日付に変換できない値が送られたとき（typeMismatch）に英語のメッセージが出ないよう、`messages.properties` に `typeMismatch=入力形式が正しくありません` を書く
- プルダウン・ラジオは enum の定数名を送り、表示は `label`
- 任意の文字列項目が空文字なら Service で `null` にして保存

### 1.6 標準画面遷移（個体・里親・イベント・スタッフ共通）

ヘッダー: ログイン後の全画面で表示。トップ / 個体一覧 / 里親一覧 / イベント / スタッフ一覧  <br>右端にログイン中の団体名と名前 / ログアウト（POST フォーム）

|遷移元|操作|遷移先|
|:---:|:---:|:---:|
|一覧|「新規登録」| 新規登録画面（GET /xxx/new）|
|一覧| 行・カードをクリック | 詳細（GET /xxx/{id}）|
|詳細|「編集」|編集画面（GET /xxx/{id}/edit）|

|新規登録・編集| 「キャンセル」 | 新規 → 一覧、編集 → 詳細 |


各機能の章では、この表と**違うところだけ**書く。


### 1.7 命名

基本設計8章のとおり。追加分: Service のメソッドは `search` `findById` `findXxxList` `getEditForm` `create` `update` `delete`（イベントだけ `complete` `uncomplete`）。`getEditForm` は編集画面用に、取得した Entity の値を Form に詰めて返す。検索条件は `XxxSearchForm`、Model 名は `searchForm`（Controller の引数に `@ModelAttribute("searchForm")` を付ける）。BOOLEAN のフィールドは `is_` を付けない（`birthdayEstimated`。列名は `@Column(name = "is_birthday_estimated")`）。避妊去勢は enum `NeuterStatus`（`DONE` 済 / `NOT_DONE` 未 / `UNKNOWN` 不明）で、列名・フィールド名とも `neutered`。

### 1.8 共通部品

- `jsp/common/header.jspf`: taglib 宣言（`c` `fn` `form` `sec`）、ナビ、ログイン中の団体名と名前（`LoginUserModelAdvice`（`@ControllerAdvice`）が全画面に `loginUser` を渡しているので、`${loginUser.organizationName}` `${loginUser.name}` で読む）、ログアウトの `<form:form action="/logout" method="post">`、フラッシュの表示。ナビ・団体名と名前・ログアウトは `<sec:authorize access="isAuthenticated()">` で囲む（login.jsp と error.jsp は未ログインでも表示されるため。囲まないと団体名の取得で例外になる）
- `static/js/confirm.js`: `confirmSubmit(msg)`。削除・完了・未対応に戻すの form に `onsubmit="return confirmSubmit('...')"` と書く（`return` が無いと、キャンセルしても送信される）
- `static/js/calendar.js`: イベント一覧の概要ペインの表示（S-07）
- `static/img/placeholder-dog.png` `placeholder-cat.png`: 写真が無い個体に犬猫で出し分け
- 年齢は Entity の `@Transient getAge()` で誕生日から計算。無ければ「不明」

- 「誕生日は推定」は `<form:checkbox>` で書く。チェックを外して送るとブラウザは値を送らないが、`<form:checkbox>` が自動で入れる隠し項目（`_birthdayEstimated`）のおかげで `false` が入る。Form のフィールドは `boolean`。誕生日が空でもチェックはそのまま保存する（年齢は「不明」と表示されるので影響しない）。
- 品種のプルダウンは、犬猫がまだ選ばれていないときは `disabled`（選べない）にする。犬猫のラジオを選ぶと JS で有効にし、選んだ犬猫の品種だけを出す。各 option は `<c:forEach>` + `<form:option value="${b.id}" data-species="${b.species}">` で書く（`<form:options>` では `data-species` を付けられない）。JS は画面を開いたときに全部の option を配列に覚えておき、犬猫を選ぶたびに「未選択」以外を外して、その犬猫のものだけを入れ直す（option を `hidden` や `display:none` で隠す方法は、iPhone の Safari では効かないため使わない）。犬猫を切り替えたら、品種の選択を「未選択」に戻す。入力エラーの再表示や編集のときに犬猫が選ばれていれば、最初から絞った状態で表示する。`disabled` の間は値が送られないが、品種は任意なのでエラーにはならない。
- 品種が選択肢に無いときは「新しい品種」に入力する。同じ犬猫・同じ名前の品種がすでにあればそれを使い、無ければ `breeds` に登録してから個体に設定する。品種マスタは全団体共通なので、登録した品種は他の団体の選択肢にも出る。

| 登録（new）| F-08 → S-04 |
| 更新（edit）| F-10 → S-04 |
| キャンセル | new → S-03、edit → S-04 |

### 3.2 機能（F-05 〜 F-11）

#### F-05 GET /animal（AnimalController#list）
1. `AnimalSearchForm`（`speciesList` `List<Species>`、`statusList` `List<Status>`。どちらも任意）を受ける
   - `@ModelAttribute("searchForm") AnimalSearchForm form, @RequestParam(required = false) String search`
   - チェックボックスは `<form:checkboxes>` で書き、検索ボタンには `name="search" value="1"` を付ける。`search` が null のとき（一覧を初めて開いたとき）だけ、`statusList` に `Status.inCare()` を入れる。チェックを全部外して検索したときは `search` があるので、初期値は入れない（全部が表示される）
2. `animalService.search(loginUser.getOrganizationId(), form)`
   - → null または空のリストは「全部」に置き換える（`speciesList` が空なら `Species.values()` の全部）
   - → `animalRepository.findByOrganizationIdAndSpeciesInAndStatusInOrderByIdDesc(organizationId, speciesList, statusList)`
3. Model: `animalList`、`searchForm`、`speciesList`、`statusList` → animal/list.jsp
   - Model の `speciesList` `statusList` はチェックボックスの選択肢（`Species.values()` `Status.values()`）。`searchForm` の中の同じ名前のフィールド（チェックされた値）とは別物

#### F-06 GET /animal/{id}（AnimalController#detail）
1. `animalService.findById(id, loginUser.getOrganizationId())` → `animalRepository.findByIdAndOrganizationId(id, organizationId)`、空なら 404
2. `animalService.findEventList(id, organizationId)` → `eventRepository.findByOrganizationIdAndAnimalIdOrderByEventDateDescEventTimeDesc(organizationId, id)`
3. Model: `animal`、`eventList` → animal/detail.jsp

#### F-07 GET /animal/new（AnimalController#newForm）
1. 空の入力フォームを用意する。
   - `new AnimalForm()`
   - 初期値を入れる: `status` = `Status.NOT_ADOPTABLE`、`neutered` = `NeuterStatus.UNKNOWN`、`birthdayEstimated` = `true`（DB の初期値と同じ）
2. ラジオボタンとプルダウンの選択肢を用意する。
   - `Species.values()`（犬 / 猫。表示は `label`）
   - `Sex.values()`（オス / メス / 不明。表示は `label`）
   - `NeuterStatus.values()`（済 / 未 / 不明）
   - `Status.values()`（保護状況8種類）
   - `animalService.findBreedList()` → `breedRepository.findAll()`（品種。全団体共通）
   - `animalService.findAdopterList(organizationId)` → `adopterRepository.findByOrganizationIdOrderByIdDesc(organizationId)`（里親。自団体だけ）
   - ワクチンは済/未の2択なので、選択肢の一覧は作らず JSP に直接書く
3. 新規登録モードで画面を表示する。
   - Model: `animalForm`、`speciesList`、`sexList`、`statusList`、`neuterStatusList`、`breedList`、`adopterList`、`mode`="new" → animal/form.jsp
- 権限は `SecurityConfig` で制御（ボランティアがURLを直接開いたら403）

#### F-08 POST /animal/new（AnimalController#create）
1. 入力値を`AnimalForm`で受け取り、入力チェックを行う。
   - `@Validated AnimalForm animalForm, BindingResult result`
2. 入力エラーがあれば、同じフォームを再表示する。（リダイレクトしない）
   - Model: `animalForm`、`speciesList`、`sexList`、`statusList`、`neuterStatusList`、`breedList`、`adopterList`、`mode`="new" → animal/form.jsp
3. アノテーションで書けないチェックをしてから、個体を登録する。団体はフォームからではなくログイン情報から設定する。
   - `animalService.create(animalForm, result, loginUser.getOrganizationId())`
   - → `newBreedName`（前後の空白を除く）が入力されているときは、`breedId` のチェックをしない（新しい品種を優先するため）。それ以外で `breedId` 指定時は `breedRepository.findById`。空、または品種の `species` が個体の `species` と違えば `result.rejectValue("breedId", ...)`
   - → 保護状況がトライアル中・譲渡済のとき: `adopterId` が空なら `result.rejectValue("adopterId", ...)`。指定時は `adopterRepository.findByIdAndOrganizationId` で引き直し、空なら rejectValue
   - → 保護状況がそれ以外のとき: `adopterId` は見ない（チェックもしない）。保存時に里親を null にする
   - → `species` が `DOG` で `rabiesVaccine` が null なら `result.rejectValue("rabiesVaccine", ...)`
   - → 写真の種類（`getContentType()`）が `image/jpeg` `image/png` 以外なら `result.rejectValue("photo", ...)`
   - → エラーがあれば保存せずに戻る（Controller が 2. と同じく再表示）
   - → `newBreedName` が入力されていれば `breedRepository.findBySpeciesAndName(species, newBreedName)` で探し、無ければ `breedRepository.save(new Breed(species, newBreedName))` で登録して、個体の品種にする
   - → Formの値を`Animal`に詰め替え、`microchipNo` `healthNotes` `notes` が空文字なら null に変換。`species` が `CAT` なら `rabiesVaccine` を false にする。保護状況がトライアル中・譲渡済以外なら `adopter` を null にする
   - → `organization` = `organizationRepository.getReferenceById(organizationId)`
   - → 写真が選ばれていれば、UUID + 拡張子のファイル名で `uploads/photos/` に保存し、`imagePath` に `/photos/xxxx.jpg` を入れる。拡張子は判定した種類から `.jpg` / `.png` を付ける（元のファイル名の拡張子は使わない）
   - → `animalRepository.save(animal)`、登録された `id` を返す。
4. フラッシュメッセージを設定し、登録した個体の詳細へリダイレクトする。
   - フラッシュ「個体新規登録が完了しました」→ `redirect:/animal/{id}`（F-06）

#### F-09 GET /animal/{id}/edit（AnimalController#editForm）
1. パス変数 `id`（Integer）を受ける。
2. 編集する個体を取得する。他団体のデータを編集させないよう団体IDも条件に含める。
   - `animalService.getEditForm(id, loginUser.getOrganizationId())` → `animalRepository.findByIdAndOrganizationId(id, organizationId)`。空なら `ResponseStatusException(HttpStatus.NOT_FOUND)`
3. 取得した`Animal`の値を`AnimalForm`に詰めて返す。（null の項目は空欄表示）
4. 編集モードで画面を表示する。
   - 現在の写真を表示するため、Controller は `animalService.findById(id, organizationId)` で `Animal` を取り、その `imagePath` を Model に入れる
   - Model: `animalForm`、`animalId`、`imagePath`、`speciesList`、`sexList`、`statusList`、`neuterStatusList`、`breedList`、`adopterList`、`mode`="edit" → animal/form.jsp
- 権限は `SecurityConfig` で制御（ボランティアは403）

#### F-10 POST /animal/{id}/edit（AnimalController#update）
1. パス変数 `id`（Integer）と入力値`AnimalForm`を受け取り、入力チェックを行う。
   - `@PathVariable Integer id, @Validated AnimalForm animalForm, BindingResult result`
2. 入力エラーがあれば、同じフォームを再表示する。（リダイレクトしない）
   - Model: `animalForm`、`animalId`、`imagePath`、`speciesList`、`sexList`、`statusList`、`neuterStatusList`、`breedList`、`adopterList`、`mode`="edit" → animal/form.jsp
   - `imagePath` は F-09 と同じく `animalService.findById` で取る
3. アノテーションで書けないチェックをしてから、個体を更新する。更新前に団体ID付きで取り直す。
   - `animalService.update(id, animalForm, result, loginUser.getOrganizationId())`
   - → `animalRepository.findByIdAndOrganizationId(id, organizationId)`。空なら `ResponseStatusException(HttpStatus.NOT_FOUND)`
   - → F-08 の 3. と同じチェック。エラーがあれば保存せずに戻る（Controller が 2. と同じく再表示）
   - → `newBreedName` が入力されていれば、F-08 と同じ手順で品種を設定する
   - → 取得した`Animal` に Form の値を上書き。`microchipNo` `healthNotes` `notes` が空文字なら null に変換。`species` が `CAT` なら `rabiesVaccine` を false にする。保護状況がトライアル中・譲渡済以外なら `adopter` を null にする（トライアル中・譲渡済から戻したとき、里親の紐づきが残らないようにするため。残ると、里親詳細（S-12）に出ないのに里親を削除できなくなる）
   - → `organization` `createdAt` は変更しない
   - → 写真が選ばれていれば F-08 と同じく保存して `imagePath` を差し替え、古い写真ファイルは `Files.deleteIfExists` で削除する。
   - → `animalRepository.save(animal)`
4. フラッシュメッセージを設定し、個体詳細へリダイレクトする。
   - フラッシュ「個体を編集しました」→ `redirect:/animal/{id}`（F-06）

#### F-11 POST /animal/{id}/delete（AnimalController#delete）
1. パス変数 `id`（Integer）を受ける。
2. 削除する個体を取得する。他団体のデータを削除させないよう団体IDも条件に含める。
   - `animalService.delete(id, loginUser.getOrganizationId())` → `animalRepository.findByIdAndOrganizationId(id, organizationId)`。空なら `ResponseStatusException(HttpStatus.NOT_FOUND)`
3. 削除する。紐づくイベントは DB の CASCADE で一緒に消えるので、紐づきの確認は不要。
   - `animalRepository.delete(animal)`
   - → `imagePath` が null でなければ、`uploads/photos/` の写真ファイルも削除する（`Files.deleteIfExists`）
4. フラッシュメッセージを設定し、個体一覧へリダイレクトする。
   - フラッシュ「個体を削除しました」→ `redirect:/animal`（F-05）
- 権限は `SecurityConfig` で制御（管理ユーザー以外は403）
- 削除ボタン押下時は `confirm.js` で「紐づくイベントと写真も削除されます。本当に削除しますか？」を表示（S-04）

#### S-07 イベント一覧（event/calendar.jsp）

![イベント一覧](img/page_detail/s-07.png)

画面の動き
- 月間カレンダーでその月のイベントを表示する。初期表示は今月。
- ◁▷で前月・次月に切り替える（`/event?year=&month=`）
- 同じ日に複数のイベントがあれば縦に並べる
- イベントバーは未対応と対応済で色を分ける。
- バーをクリックすると、概要ペインにそのイベントを表示する。
- 対応済のスタンプを押すと、確認のうえ、未対応に戻す。
- スタンプ欄は、概要ペインに `<form:form method="post">` を1つ置き、バーをクリックしたときに JS で `action` を `/event/{id}/complete`（未対応のとき）か `/event/{id}/uncomplete`（対応済のとき）に差し替える。JS で `<form>` を新しく作ると CSRF トークンが入らず、403 になる。確認メッセージも `action` と一緒に差し替える（form に `data-msg` を持たせ、`onsubmit="return confirmSubmit(this.dataset.msg)"` と書く）。
- ボランティアにはスタンプ欄（ボタン）ごと出さず、代わりに対応状況を文字（未対応／対応済）で出す。スタンプ欄の form を `<sec:authorize access="hasAnyRole('ADMIN','STAFF')">`、文字の要素を `<sec:authorize access="!hasAnyRole('ADMIN','STAFF')">` で囲む。JS はバーをクリックしたとき、スタンプ欄の form があれば `action` と確認メッセージを差し替え、無ければ（ボランティア）文字の要素に「未対応」か「対応済」を入れる。

|イベントバー|個体名`${e.animal.name}`、`${e.eventType.name}`|dが持つイベント一覧をループ（e）|

ペインの値はすべてバーのdata属性からJSで表示する。文字はすべて `fn:escapeXml` でエスケープする。JS は `innerHTML` ではなく `textContent` でペインに入れる（`innerHTML` だとエスケープが無効になる）。

### 4.2 機能（F-12 〜 F-19、F-34）

#### F-12 GET /event（EventController#list）
1. 表示する年月 `year` `month`（Integer。どちらも任意）を受ける。
   - `@RequestParam(required = false) Integer year, @RequestParam(required = false) Integer month`
   - year か month のどちらかが未指定、または month が 1〜12 以外なら今月を表示する。数字でない値（`year=abc` など）は 400 になり error.jsp が出る（URL を手で書き換えたときだけ起きるので、そのままにする）。
2. カレンダーを組み立てる。
   - `eventService.search(loginUser.getOrganizationId(), year, month)`
   - → 表示期間は「1日を含む週の日曜」〜「末日を含む週の土曜」（前月・次月のはみ出したマスも含む）
   - → `eventRepository.findByOrganizationIdAndEventDateBetweenOrderByEventDateAscEventTimeAsc(organizationId, 開始日, 終了日)`
   - → 取得したイベントを日ごとに振り分け、`EventCalendar` を作って返す。
3. Model: `calendar` → event/calendar.jsp
- 前月・次月は `YearMonth` の `minusMonths(1)` `plusMonths(1)` で求める（12月の次月は翌年1月になる）。
- F-01（トップページ）も同じ `eventService.search(organizationId, null, null)` で今月のカレンダーを作る。

`EventCalendar`（カレンダー1か月分）

|フィールド|型|内容|
|---|---|---|
|year|int|表示中の年|
|month|int|表示中の月|
|prevYear / prevMonth|int|前月の年・月（◁ のリンク用）|
|nextYear / nextMonth|int|次月の年・月（▷ のリンク用）|
|weeks|`List<List<CalendarDay>>`|週のリスト。1週は日曜〜土曜の7日|

`CalendarDay`（カレンダー1マス分）

|フィールド|型|内容|
|---|---|---|
|date|`LocalDate`|日付|
|day|int|日（1〜31）。JSPでは `${d.day}`|
|inMonth|boolean|表示中の月の日なら true。false のマスは薄く表示|
|eventList|`List<Event>`|その日のイベント（時刻順）|

`EventCalendar` と `CalendarDay` は `com.example.hogotaro.dto` パッケージに置く。画面に渡すための入れ物で、テーブルとは対応しない（Entityではない）。

#### F-15 POST /event/new（EventController#create）

   - → Formの値を`Event`に詰め替え、`place` `notes` が空文字なら null に変換。`done` は false、`staff` は null。

### 5.2 機能（F-20 〜 F-26）

#### F-20 GET /adopter（AdopterController#list）
1. `AdopterSearchForm`（`name` `phoneNumber`。どちらも任意）を受ける。
   - `@ModelAttribute("searchForm") AdopterSearchForm form`（検索したあとも、入力欄に検索した文字が残る）
2. 名前・電話番号とも部分一致で絞り込む。未入力なら、その条件では絞らない（全件に当たる）。電話番号はハイフンを無視して比べる（`080-1111` でも `0801111` でも同じ里親が当たる）。
   - `adopterService.search(loginUser.getOrganizationId(), form)`
   - → `name` が null なら空文字にし、前後の空白を除く
   - → `phoneNumber` が null なら空文字にし、ハイフン（`-`）を取り除いて、前後の空白を除く
   - → `adopterRepository.search(organizationId, name, phone)`。**null は渡さない**（`concat('%', null, '%')` は null になり、どの行にも当たらず0件になる）。空文字なら `like '%%'` で全件に当たる
   - `@Query` には団体の条件を必ず入れる（無くてもエラーにならず、他団体の里親が出てしまう）: `select a from Adopter a where a.organization.id = :organizationId and a.name like concat('%', :name, '%') and replace(a.phoneNumber, '-', '') like concat('%', :phone, '%') order by a.id desc`。メソッドの引数には `@Param("organizationId")` `@Param("name")` `@Param("phone")` を付ける
3. 絞り込みの候補として、自団体の名前一覧・電話番号一覧を取得する。（Repository にまだ無い。一覧と検索が動いてから足す）
   - `adopterService.findNameList(organizationId)` → `adopterRepository.findNameList(organizationId)`（`@Query` で `select distinct a.name from Adopter a where a.organization.id = :organizationId order by a.name`）
   - 電話番号も同じ形で `findPhoneNumberList(organizationId)`
4. Model: `adopterList`（検索結果）、`searchForm`、`nameList`（名前の候補）、`phoneNumberList`（電話番号の候補） → adopter/list.jsp

   - `eventRepository.existsByOrganizationIdAndAdopterId(organizationId, id)`
   - どちらかが true なら false を返す。
   - → フラッシュ「個体またはイベントに紐づいているため削除できません」→ `redirect:/adopter/{id}`（F-21）
4. 紐づきがなければ削除し、true を返す
   - `adopterRepository.delete(adopter)`
   - → フラッシュ「里親を削除しました」→ `redirect:/adopter`（F-20）
- 権限は `SecurityConfig` で制御（管理ユーザー以外は403）
- 削除ボタン押下時は `confirm.js` で「本当に削除しますか？」を表示（S-12）

3. アノテーションで書けないチェックをしてから、スタッフを更新する。更新前に団体ID付きで取り直す。

   - → `loginId` `organization` `createdAt` は変更しない
   - → `staffRepository.save(staff)`（`updated_at` は DB が自動で更新する）
4. フラッシュメッセージを設定し、スタッフ詳細へリダイレクトする。
   - フラッシュ「スタッフを編集しました」→ `redirect:/staff/{id}`（F-28）

## 7. エラー

### 7.1 画面（S-19）

#### S-19 エラー（error.jsp）

カンプは無し。メッセージと、トップページへのリンクだけを表示する。


Java のクラスは書かない。`server.error.whitelabel.enabled=false` にしておくと Spring Boot が 403 / 404 / 413 / 500 で `jsp/error.jsp` を表示する。`${status}` で文言を分ける。

|`${status}`|文言|
|:---:|---|
|403|この操作を行う権限がありません|
|404|指定されたデータは存在しません|
|413|ファイルは 5MB 以下にしてください|
|その他|システムエラーが発生しました|

- 404 は Service が `throw new ResponseStatusException(HttpStatus.NOT_FOUND)`
- 403 は Spring Security。生の `<form>` で POST しても（CSRF）403 になるので、POST は必ず `<form:form>`
- 5MB を大きく超える写真を送ると、Tomcat が途中で接続を切り、error.jsp ではなくブラウザの接続エラーになることがある。その場合は application.properties に `server.tomcat.max-swallow-size=-1` を足す。`spring.servlet.multipart.max-request-size` も 5MB より大きくしておく
- 土台を動かしたら、存在しない URL・V で POST・6MB の画像・20MB の画像の 4 つを試して、error.jsp にそれぞれの文言が出ることを確かめる

### 8.3 状態遷移図

#### 個体の保護状況（`animals.status`）

```mermaid
stateDiagram-v2
    [*] --> NOT_ADOPTABLE : 個体を登録（初期値）

    state "保護頭数に数える（Status.inCare()）" as inCare {
        NOT_ADOPTABLE : 保護中(譲渡不可)
        ADOPTABLE : 保護中(譲渡可)
        HOSPITALIZED : 入院中
        TRIAL : トライアル中

        NOT_ADOPTABLE --> ADOPTABLE : 譲渡できる状態になった
        ADOPTABLE --> NOT_ADOPTABLE : 譲渡を見合わせる
        NOT_ADOPTABLE --> HOSPITALIZED : 入院
        ADOPTABLE --> HOSPITALIZED : 入院
        HOSPITALIZED --> NOT_ADOPTABLE : 退院
        ADOPTABLE --> TRIAL : トライアル開始
        TRIAL --> ADOPTABLE : トライアル返却
    }

    ADOPTED : 譲渡済
    RETURNED : 返還
    TRANSFERRED : 移管
    DECEASED : 死亡

    TRIAL --> ADOPTED : 正式に譲渡
    inCare --> RETURNED : 元の飼い主へ返す
    inCare --> TRANSFERRED : 他団体・行政へ引き継ぐ
    inCare --> DECEASED : 死亡
    ADOPTED --> [*]
    RETURNED --> [*]
    TRANSFERRED --> [*]
    DECEASED --> [*]
```

- 図は業務で想定している流れ。保護状況は個体の新規登録（F-08）・編集（F-10）のプルダウンで選ぶので、システムは図に無い変更も止めない（入力ミスを直せるようにするため）。
- 保護状況を変えるのは個体の登録・編集だけ。イベントを完了にしても変わらない（入院・退院・トライアル開始・トライアル返却・譲渡のイベントも同じ。一部の矢印はイベント種別と同じ名前だが、個体の保護状況はスタッフが個体の編集で変える）。
- 保護状況がトライアル中・譲渡済のときは、里親の選択が必須（F-08・F-10 のチェック）。それ以外の保護状況で保存すると、里親は空になる（トライアル返却などで保護中に戻したときも同じ）。
- 譲渡済・返還・移管・死亡は記録として残す状態で、保護頭数には数えない。

#### イベントの対応状況（`events.done`）

|状態|`done`|`staff`|次の状態へ進む操作|
|---|:---:|---|---|
|未対応|false|null|スタンプ欄をクリック → F-18 → 対応済|
|対応済|true|完了にしたスタッフ|済スタンプをクリック → F-34 → 未対応|

- 新規登録（F-15）したイベントは未対応から始まる。
- 対応状況が変わるのは F-18 と F-34 だけ。編集（F-17）では変わらない。
- 対応済のスタッフが削除されると、`staff` は null になる（`ON DELETE SET NULL`）。対応済のままで、対応スタッフだけ表示されなくなる（S-08）。
